# 无限流角色卡网页（InfWeb）

基于 HTML5 Boilerplate 的静态项目，前端源码在 `src/`，纯前端（ES Module）+ 静态数据，无需构建即可部署。

## 一、模块构成（三层架构，便于迁移 Vue / 接后端）
- `index.html`：侧边栏菜单 + 内容区 `#app` + 用户栏，ES Module 加载脚本。
- `css/style.css`：全站样式。
- `js/character-config.js` — **字段单一数据源**（九属性 / 二十一技能 / 三分组，id 稳定可作 API 字段名）。
- `js/store.js` — **状态 + 持久化**（`emptyCharacter()`、`api.save/load`，现走 localStorage，后端预留）+ 动态行工厂。
- `js/app.js` — **渲染与交互**（原生 DOM）：主页面/应用切换、角色管理、角色卡 sheet、动态行、数值计算、路由。
- `js/rules.js` — **规则书**：零依赖 Markdown 渲染器 + 规则书页。

依赖：`app.js → character-config / store / rules`；`rules.js → fetch content/rules/*.md`；`src/content/rules` 由 `scripts/docx2md.py` 从 `Rules/*.docx` 生成。

## 二、页面
主页面(landing) → 进入 → 应用（角色管理 / 规则书 / 更新记录 / 资源列表 / 轮回之境 / 其他）。角色卡分 sheet：总览 / 属性 / 法术 / 特殊攻击 / 能量池 / 专长 / 装备 / 特性 / 资源。

## 三、数值公式（摘录）
- 属性值 = 基础 + 内在 + 修行 + 器械 + 完美 + 其它；传奇属性 = ⌊(属性值−1)/5⌋；技能附加成功 = 值≥{5,7,9,11,13,15} 个数（≤6）。
- 检定值(技能) = 基础 + 内在 + 修行 + 器械 + 完美 + 士气 + 其它。
- 法术：施法基础 = 智力检定 + 神秘学检定 + 加成1..6；法术DP = 基础 + 威力 + 专业 + 加成；伤害上限 = 智力基础 + 神秘学基础 + (专业>0?1:0) + 传奇智力×2 + 伤害加成。
- 特殊攻击 DP = 属性值 + 技能值 + 武器伤害 + 专业 + 加成 + 附加成功(技能)。
- 能量池总值 = 关键属性1 + 属性2(可选) + 加成1..3。
- 专长已用点 = Σ 逐级累加（目标3级=1+2+3=6），上限 15。

### 建卡（快速创建角色卡）
1. 概念段：姓名 / 性别（种族）/ 年龄 / 身高体重 / 外貌 / 背景 / 总资源量。
2. 属性：九项全默认 2；5/4/3 定向点分给生理/心智/互动；4→5 需 2 点；建卡上限 6。
3. 技能：全默认 0；6/5/4 定向点按大类分配；3→4 需 2 点；另 5 自由点；建卡不可到 5。
4. 专长：15 点；1 点=1 级；分档专长需从低到高买。

### 派生值
- 生命 = 5 + 耐力检定 + 传奇耐力⌊N(N+1)/2⌋
- 意志 = 决心检定 + 沉着检定 + 传奇决心×3 + 传奇沉着
- 先攻 = 敏捷检定 + 沉着检定 + 传奇沉着×3
- 移动 = 5 + 力量检定 + 敏捷检定 + 传奇敏捷×3
- 豁免（各 + 传奇对应×3）：反射=敏捷+运动；意志=决心+感受；强韧=耐力+求生

### 其他
- 属性归零：力量0→倒地、敏捷0→僵死、耐力0→死亡、其余→昏厥。
- 升级价格：属性 `当前值×100` 金钱 / `当前值×3xp`；技能 `当前等级×2xp`（0→1 为 1xp）。

## 四、运行方式
```powershell
python -m http.server 8080 --directory src   # 或 npx serve src
```
访问 `http://localhost:8080`（ES Module 需静态服务器，不能 file:// 直开）。

GitHub Pages 部署（`src/` → `InfWebPages`）：正常终端提交推送后，
```powershell
git subtree push --prefix=src pages master:main
```

> **缓存规避**：改 `js/*.js` 或 `css/style.css` 后，记得同步更新 `src/index.html` 里引用的版本参数（如 `css/style.css?v=xxx`、`js/app.js?v=xxx`）。否则浏览器/CDN 可能仍使用旧缓存，导致线上不生效（常见现象：本地正常、部署后变化看不到）。

## 五、更新记录数据源规范
「更新记录」页读取 `src/content/updates/changelog.json` 渲染。**注意：JSON 不支持注释**。

数据源是**对象数组**，方向约定：**越靠上方=越旧、越靠下方=越新**，页面倒序展示（最新在最上）。

字段：
| 字段 | 必填 | 说明 |
| --- | --- | --- |
| `title` | ✅ | 更新标题（加粗，左上角） |
| `content` | ✅ | 更新内容，纯文本；推荐用数组（每元素一段），也兼容单字符串（含 `\n` 自动拆段） |
| `date` | ✅ | `YYYY-MM-DD`（也接受 `YYYY/M/D`，自动补零） |

**三种编辑模板见 `src/content/updates/changelogTemplate.json`**（结构与 changelog.json 相同，三个条目各演示一种写法：①普通文本 ②换行符 ③数组）。复制对应条目、替换内容后粘到 changelog.json **数组末尾**即可。

维护约定：新增条目放数组末尾（最新在下，页面显示在上）；旧条目保留不删；`content` 不要用 Markdown；空元素自动跳过。格式由 `test/characters-page.mjs` 校验。

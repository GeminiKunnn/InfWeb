# 工作记录 — 无限流角色卡网页

> 本文档简要记录项目开发情况：各模块构成、引用依赖关系、用到的数值计算公式，
> 以及常引用的规则书内容，方便日后查阅。

## 一、模块构成

项目基于 IDEA 创建的 HTML5 Boilerplate 静态项目（`InfWeb.iml`，WEB_MODULE），
前端源码位于 `src/`，构建产物目录 `dist/`（由模板自带 gulp/webpack 处理）。

### 1. 页面骨架
- **`src/index.html`**
  - 左侧垂直菜单栏 `#sidebar`（顶部折叠按钮 + 点击回主页的「无限流」logo + 菜单项：角色管理 / 规则书 / 轮回之境 / 其他）
  - 右侧内容区 `#app`（页面渲染容器，未来 Vue 根组件挂载点）
  - 底部用户栏（用户名 + 下拉登出，暂为界面）
  - 使用 ES Module 加载脚本（`<script type="module" src="js/app.js">`）

### 2. 样式
- **`src/css/style.css`**：侧边栏、字符卡片分区、属性/技能表、sheet 标签、动态行、按钮等。

### 3. JavaScript（三层架构，便于未来迁移 Vue / 接后端）
| 文件 | 职责 |
| --- | --- |
| `js/character-config.js` | **字段定义单一数据源**：九属性、二十一技能、三分组（id 稳定，可作 API/Vue 字段名） |
| `js/store.js` | **状态 + 持久化**：`emptyCharacter()` 状态对象、`api.save/load`（现走 localStorage，后端预留）、动态行工厂 `newSpell()/newAttack()/newEnergyPool()/newPerk()/newEquipment()/newTrait()/newPurchase()/newRecord()/newReduction()` |
| `js/app.js` | **渲染与交互**（原生 DOM）：主页面/应用界面切换、角色管理页、角色卡 sheet 切换、动态行增删、数值自动计算、规则书/轮回之境路由 |
| `js/rules.js` | **规则书模块**：零依赖 Markdown 渲染器 + 规则书页（选择器 + 侧边竖向目录 + 滚动高亮） |

### 4. 角色卡内部表单（sheet 标签切换）
`角色总览` / `角色属性` / `法术列表` / `特殊攻击` / `能量池` / `专长` / `装备` / `特性` / `资源`
- **角色总览**：概念段、属性卡片网格（一行三个）、技能段按 生理/心智/互动 分区（每行三个）、生命值（含状态明细，置于派生值上方）、派生值（意志/先攻/移动 + 三豁免）、五种基础攻击总览、防御信息（护甲总+附加成功 / 伤害减免）、其他信息（基因锁熟练度/敏感范围）。
- **角色属性**：属性/技能完整加值栏、生命值（状态点数）、属性细则（移动/先攻/意志/生命 + 专长 + 加成1-5）、豁免检定、防御（护甲 / 伤害减免）、五种攻击方式、敏感范围、基因锁熟练度。各列表区统一为「圆角外框 + 左上标题 + 直角内表 + 左下提示」，豁免/攻击/敏感范围/熟练度均为直角表且总计实时计算。

## 二、模块引用依赖关系

```
index.html ──加载(ES Module)──▶ js/app.js
                                  │  import
                                  ├─▶ js/character-config.js   (ATTRIBUTES / SKILLS)
                                  ├─▶ js/store.js               (状态 + api + 工厂函数)
                                  └─▶ js/rules.js               (规则书渲染)
js/store.js ──import──▶ js/character-config.js
js/rules.js ──fetch──▶ content/rules/*.md   (规则书 Markdown 数据)
```
- `app.js` 依赖 `character-config.js`（字段）、`store.js`（状态）与 `rules.js`（规则书页），持有单一状态 `character`。
- `store.js` 依赖 `character-config.js` 构造默认属性/技能结构。
- `rules.js` 通过 fetch 加载 `content/rules/*.md` 并渲染；`content/rules/` 由 `scripts/docx2md.py` 从 `Rules/*.docx` 生成。
- 各模块边界清晰：改字段改 `character-config.js`，改持久化/后端改 `store.js` 的 `api`，
  改规则书展示改 `rules.js`，改界面交互改 `app.js`。迁移 Vue 时仅替换 `app.js` 渲染层。

## 三、数值计算公式

### 属性（九项，默认基础 2）
分布：生理系=力量/敏捷/耐力；心智系=智力/感知/决心；互动系=风度/操控/沉着。

```
属性值 = 基础 + 内在 + 修行 + 器械 + 完美 + 其它
传奇属性 = ⌊(属性值 − 1) / 5⌋          // 每满 5 点触发一次
附加成功(技能) = 值≥{5,7,9,11,13,15} 的个数，最多 6
```

### 技能（21 项，默认基础 0）
- 生理系(8)：运动、肉搏、枪械、躲藏、求生、白刃、手上功夫、驾驶
- 心智系(7)：学识、电脑、调查、医学、科学、神秘学、手艺
- 互动系(6)：感受、动物交谈、表达、掩饰、胁迫、交际
```
检定值 = 基础 + 内在 + 修行 + 器械 + 完美 + 士气 + 其它
```

### 法术
```
施法基础检定 = 智力检定值 + 神秘学检定值 + 加成1..6   // 法术页顶部栏，默认置顶
法术检定 DP  = 施法基础检定(即每法术「基础值」列) + 法术威力 + 专业 + 加成1..6
法术伤害上限 = 智力基础 + 神秘学基础 + (专业>0 ? 1 : 0) + 传奇智力×2 + 伤害加成1..3
```

### 特殊攻击
```
特殊攻击 DP = 属性值 + 技能值 + 武器伤害 + 专业 + 加成总和 + 附加成功(技能)
```

### 能量池
```
能量池总值 = 关键属性1 + 关键属性2(可选) + 加成1 + 加成2 + 加成3
```

### 专长 / 装备 / 特性 / 资源
- 专长已用点数 = Σ(各专长等级从 1 累加到目标等级的逐级点数)；上限 15。
  （如目标 3 级 = 1+2+3 = 6 点。）
- 装备：装备位（下拉）+ 装备名称/效果，点击添加新行；特性已独立为「特性」标签页。
- 特性：来源（血统/改造/体系等）+ 描述，点击添加新行。
- 资源：未使用资源（支线/分数/xp）、资源消耗统计（价格/内容）、资源获取记录（数量/来源），均手动填写、数字不做强制计算。

## 四、常用规则内容（摘录，方便查阅）

> 完整文本以 `Rules/` 下文档为准，此处收录开发中高频引用的片段。

### 建卡（快速创建角色卡.docx）
1. **概念段**：姓名、性别（种族）、年龄、身高体重、外貌特征、背景概述、总资源量（页面已去掉「母语」字段）。
2. **属性**：九项全默认 2；5/4/3 定向点分给生理/心智/互动；4→5 需 2 点；建卡最高 6 分。
3. **技能**：全默认 0；6/5/4 定向点分配；属性分配方式与大类相对应；三级→四级需 2 点，建卡不可到五级；另 5 自由点。
4. **专长**：15 专长点；1 点=1 级；分档专长需从低到高买（如 1-5 全套需 1+2+3+4+5=15 点）。

### 属性归零后果（基础规则.docx）
- 力量0：倒地、失去所有动作
- 敏捷0：关节僵死（类石化）
- 耐力0：**直接死亡**
- 智力/感知/决心/风度/操控/沉着0：昏厥（各有描述）

### 派生值（已在角色属性页实现）
```
生命值 = 5(基础) + 耐力检定值 + 传奇耐力增值 ⌊N(N+1)/2⌋
意志力 = 决心检定值 + 沉着检定值 + 传奇决心×3 + 传奇沉着
先攻值 = 敏捷检定值 + 沉着检定值 + 传奇沉着×3
移动力 = 5(基础) + 力量检定值 + 敏捷检定值 + 传奇敏捷×3
豁免 DP（各 + 传奇对应属性×3）：
   反射豁免 = 敏捷检定值 + 运动检定值
   意志豁免 = 决心检定值 + 感受检定值
   强韧豁免 = 耐力检定值 + 求生检定值
```

### 传奇属性增益（基础规则.docx）
每点传奇属性：主属性攻击伤害上限+2；并按下述累加：
- 传奇力量：力量检定+n附加成功、负重×(n+1)、+n基础护甲
- 传奇敏捷：敏捷检定+n附加成功、反射豁免+n×3DP、移动力+3n
- 传奇耐力：耐力检定+n、生命+n(n+1)/2、基础护甲+n、强韧豁免+n×3DP
- 传奇智力：智力检定+n、法术伤害上限+n、冒险结算经验红利+n
- 传奇感知：感知检定+n、敏感范围+20n米
- 传奇决心：决心检定+n、意志池+3n、意志豁免+n×3DP
- 传奇风度：风度检定+n、基因锁/机运骰 +−n、意志力用法完美加值+2n
- 传奇操控：操控检定+n、每冒险 n 次重骰
- 传奇沉着：沉着检定+n、意志池+n、先攻+3n、基础护甲+n

### 技能附加成功临界（基础规则.docx）
技能达 **5、7、9、11、13、15** 时各 +1 附加成功（最多 6）；可因专长突破 15 但不再增加。

### 属性/技能升级价格
- 属性：分数 `当前基础属性值×100`；经验 `当前基础属性值×3xp`
- 技能：`当前技能等级×2xp`（0→1 为 1xp）

## 六、更新记录数据源规范

「更新记录」页直接展示 `src/content/updates/changelog.json` 中的数据，每条在页面中显示为一行：
**更新标题（左上加粗）**、**更新内容（一段平文本）**、**更新时间（年月日）**。

### 文件位置
`src/content/updates/changelog.json`（随 `src/` 一起部署上线，页面经 `fetch` 读取，无限流/无跨域）。

### 数据源方向约定（重要）
**数组中：越靠上方 = 越旧的更新，越靠下方 = 越新的更新。**
页面展示时会倒序：把数组末尾（最新）显示在最上方，越往下越旧。

### 数据结构

顶层为**对象数组**，每个元素是一条更新记录（约上方越旧、越靠下方越新）：

```json
[
  {
    "title": "较旧的一条更新",
    "content": "……",
    "date": "2026-10-08"
  },
  {
    "title": "更新标题（必填，加粗显示，左上角）",
    "content": "更新内容（必填，一段平文本，说明本次改了什么）",
    "date": "2026-10-09"
  }
]
```

### 字段说明

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| `title` | ✅ | 更新标题，非空字符串，页面左侧加粗显示 |
| `content` | ✅ | 更新内容，一段平文本（纯文本，不含 Markdown/HTML），自然换段即可 |
| `date` | ✅ | 更新时间，形如 `YYYY-MM-DD`（也接受 `YYYY/M/D`，会被规整为补零的年月日） |

### 维护约定
- **新增**：在**数组末尾**插入新条目（越靠下方越新，页面显示最新在最上方）。旧条目保留、不要删除。
- **不支持的写法**：`content` 内不要使用 Markdown 标题/加粗/列表语法，页面按纯文本展示；如需多条信息请用换行/分号分隔。
- **校验**：`test/characters-page.mjs` 会对该文件做结构校验（数组、字段必填、日期格式），跑测试即可查出格式错误。
- 缺省兼容：`title`/`content` 为空可容忍（显示空），但建议始终补齐。
